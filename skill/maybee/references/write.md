# Writing for the project

Read this before you write a post, a message, an email, an ad or any text that speaks for the project or its owner. It tells you what to read first and how to treat what you find. Where the text goes (a card in `ideas/`, a file in `outputs/`) follows [board.md](board.md).

## Read first, in this order

All paths are inside the active workspace. Skip a file that is missing or still empty: never ask the owner to fill everything before you can write, and never invent what is not there.

1. `PROJECT.md`: what the project is for and the current goal.
2. `knowledge/audience/`: who the text is for, in their words: pains, wishes, fears, objections. One file per persona; pick the one the text is for, and say which you picked.
3. `knowledge/offer/`: what is being offered and at which step of the ladder (`ladder.md`, then the product file). Write about the step the reader is at, not the most expensive one.
4. `knowledge/brand/`: how the owner sounds (`voice.md`) and the distinctive elements (`design-elements.md`).
5. `decisions/`: choices already made. They win over your own ideas.
6. Recent changes in `logs/CHANGELOG.md` and `STATE.md`, when the text should reflect real progress.

## Apply what you read

- **Voice and functional elements always apply.** Elements marked *functional* in `design-elements.md` (sentence length, how paragraphs start, tone) are writing rules: follow them in every text.
- **Cosmetic elements are optional.** An emoji, a nickname or a catchphrase is a signature, not a rule. Use one when it fits, never in every line.
- **Use the audience's own words** for the problem, taken from the pains and the phrases in `audience/`. Do not paraphrase them into generic marketing.
- **Match the offer step.** Attraction content leads to the entry product, not straight to the highest-priced one.
- **Never invent facts, numbers, results or testimonials.** If the text needs a proof point that is not in `knowledge/`, leave a clearly marked gap and ask.

## Finish

- Say in one line which files you used and which were empty, so the owner knows what would improve the next draft.
- Anything that goes out (publishing, sending, posting) is a draft that waits for the owner's explicit OK.
